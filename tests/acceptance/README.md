# Tests d'acceptation de `piighost`

Un test d'acceptation vérifie un critère d'acceptation d'une story de l'inventaire des besoins par profil (DPO, DEV, OPS, USER). Il se place à l'extérieur du code, passe par l'API publique, la CLI ou le serveur HTTP, et contrôle un résultat observable avec des valeurs littérales. Un critère donne un test, identifié `AT-<story>-<n>`.

Ce fichier liste ces tests et les confronte à la suite existante. Il ne contient pas de code de test.

## Comment lire les tableaux

- "Tests existants" cite des nœuds pytest relatifs à la racine du dépôt `piighost`. Un nœud préfixé `piighost-api:` vient du dépôt `piighost-api` (branche `feat/piighost-2`).
- Chaque nœud cité a été lu puis exécuté le 2026-10-02. Les tests de `piighost` passent avec `uv run pytest <nœud> -q`. Les tests de `piighost-api` passent avec `.venv/bin/python -m pytest <nœud> -q`, car `uv run` n'y résout pas encore `piighost>=2.0` depuis PyPI (le venv contient une installation éditable de `piighost` 2.0).
- Les tests LlamaIndex sont ignorés sans l'extra `llama-index`. Ils passent avec `uv run --with llama-index-core pytest tests/integrations/llama_index`.
- Statut : couvert (le comportement est vérifié, parfois avec d'autres valeurs que celles de l'inventaire, signalées), partiel (ce qui manque est indiqué), absent.
- Les tests de la bibliothèque utilisent `ExactMatchDetector` ou un hub simulé. La qualité de détection d'un vrai modèle ou d'un vrai groupe du hub reste hors de ces tests.

## Manquants

Classés par risque, une fuite d'abord. Les tests absents et la part manquante des tests partiels sont mêlés.

1. AT-DPO-1-2 (absent) : une clé d'API dans un message. Rien ne prouve qu'un secret part en jeton, et c'est la fuite la plus coûteuse (identifiant d'accès exploitable).
2. AT-DPO-6-1 (partiel) : restaurer un jeton après `forget_thread`. La mémoire est vidée, mais aucun test ne montre que la valeur est devenue introuvable par la voie publique, ce qui est la promesse faite au titre du droit à l'effacement.
3. AT-OPS-2-1 (absent) : deux instances sur la même base Redis. Si elles divergent, un jeton peut être restauré vers la valeur d'une autre personne.
4. AT-DPO-5-2 et AT-OPS-3-1 (partiels) : `load_thread_pipeline` sur un fichier Redis complet sans les secrets. Le refus n'est vérifié que composant par composant.
5. AT-DEV-3-2 (partiel) : restaurer dans le fil "b" un jeton émis dans le fil "a". Une erreur ici montre à un utilisateur la donnée d'un autre fil.
6. AT-DPO-2-1 (partiel) : un vrai groupe du hub (IBAN, NIR) masque ses valeurs. Seul un hub simulé est chargé.
7. AT-USER-3-2 (partiel) : arguments d'outil restaurés dans le flux OpenAI. Défaut fonctionnel connu, l'outil reçoit un jeton.
8. AT-OPS-1-1 (partiel) : `serve` sur une référence du hub puis `POST /v1/anonymize` dans un seul test.
9. AT-DEV-6-2 (partiel) : `piighost validate` sur une clé mal orthographiée, avec la clé nommée dans le message.
10. AT-DEV-1-2 (partiel) : le SDK `openai` avec seulement `base_url` changé.
11. AT-OPS-6-2 (partiel) : le cache disque vu à travers `load_pipeline`.
12. AT-DPO-2-2 (absent) : retirer un groupe laisse ses valeurs en clair.
13. AT-USER-5-2 (absent) : une date n'est pas masquée par un groupe générique (sur-masquage).
14. AT-USER-1-2 (absent) : réponse affichée restaurée sous Claude Code, à écrire quand la fonction existera.
15. AT-DPO-8-1 (absent) : contenu de la page AIPD, contrôlable par un test de documentation.

## En trop ou hors liste

### a. Tests sans valeur d'acceptation ou en double

- `tests/pipeline/test_thread.py::TestDefaults::test_the_default_pipeline_stays_thread_stable` double `tests/pipeline/test_thread.py::TestThreadConsistency::test_a_value_keeps_its_token_across_messages` : mêmes messages, mêmes assertions, et le `_pipeline()` du second construit exactement les composants par défaut du premier. L'un des deux suffit, ou le premier peut se limiter à vérifier les défauts.

## Ce que l'inventaire devrait ajouter

- DPO-1 : nommer le groupe de secrets (référence du hub et label attendu), sinon AT-DPO-1-2 ne peut pas s'écrire avec une valeur littérale.
- DPO-1 : ajouter "aucun tour suivant, aucun bloc de contenu et aucun argument d'outil ne renvoie une valeur en clair", car c'est là que les fuites ont été corrigées.
- DPO-1 : ajouter "un jeton tapé par l'utilisateur ne fait pas apparaître la valeur d'un autre", propriété de sécurité déjà testée mais promise nulle part.
- DPO-6 : reformuler le critère en "restaurer un jeton du fil effacé rend le jeton tel quel", observable par l'API publique.
- DPO-7 : préciser le rédacteur. Le critère cite "<<PERSON:1>>", les tests utilisent `RedactPlaceholderFactory` qui produit "<<REDACT>>".
- DPO-9 (nouvelle) : décider de l'échec d'un détecteur (`LLMDetector` rend zéro détection sur une sortie mal formée). Une détection qui échoue en silence laisse passer la donnée.
- DEV-3 : écrire "deux fils différents ne restaurent pas les jetons l'un de l'autre" plutôt que "ne partagent pas leurs jetons", qui est faux au sens littéral (les deux fils émettent "<<PERSON:1>>").
- DEV-10 (nouvelle) : sans `thread_id`, l'intégration refuse plutôt que de tout verser dans le fil `default`.
- DEV-11 (nouvelle) : une valeur que l'assistant introduit reste en clair, et le choix est réglable (`EntityCreateByAssistantStrategy`).
- OPS-3 : "pas de démarrage en clair" n'est vrai que si hasher et cipher sont configurés. Sans les deux, Redis démarre en clair avec un `PIIGhostSecurityWarning`. Le critère doit le dire, ou exiger un refus.
- OPS-4 : ajouter "une clé mal formée sans `PIIGHOST_ALLOW_ANONYMOUS` empêche le démarrage" et "une route protégée sans jeton répond 401".
- OPS-7 (nouvelle) : l'exploitant ne charge du hub que des groupes de motifs, par HTTP(S), et seules les références épinglées sont mises en cache.
- OPS-8 (nouvelle) : la mémoire en processus est bornée en nombre de fils et en durée, pour qu'un serveur ne garde pas indéfiniment des valeurs.
- USER-4 : nuancer "jamais "<<PER" à l'écran". Un flux coupé au milieu d'un jeton rend le fragment à la fin, par choix (aucune valeur réelle n'y figure).
- USER-6 (nouvelle) : l'utilisateur ou un relecteur corrige une détection manquée ou fausse dans un fil (`anonymize_corrected`), fonction utilisée par `piighost-chat`.
